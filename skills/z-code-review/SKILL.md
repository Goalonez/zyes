# 审查代码改动

## 确定范围

使用调用方指定的 diff、提交或改动范围。未指定时，检查当前工作区的暂存、未暂存改动及未跟踪文件；范围仍不明确时询问调用方。

## 审查

- 沿改动读取必要的调用方、配置和测试，核实触发条件与实际影响。
- 关注正确性、安全边界、行为回归和关键测试缺口，仅报告有依据、可行动的问题。
- 复用已有验证结果，证据不足时按需补充针对性检查。

## 输出

按严重程度列出问题，给出文件位置、触发条件和影响，简述必要的修复方向。区分确认的问题与待确认的疑点，说明未验证项和判断边界。

没有发现可行动的问题时，明确说明。默认只报告审查结论，修复由调用方处理。
